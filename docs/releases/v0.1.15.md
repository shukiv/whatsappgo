# WhatsAppGo v0.1.15

Thirty-two commits since v0.1.14. WhatsAppGo gains a second front end: a
terminal client that talks to the same background service as the window,
so a fix in the service reaches both. It reads and answers conversations,
acts on messages, opens media and plays voice notes, and is drawn the way the
window is - bubbles, the conversation list with its discs and unread pills,
the attach menu and the emoji panel - with the mouse as well as the keys. The
AppImage carries it, and `--tui` opens it in place of the window.

Ctrl+Enter is now the key that sends, in the message box and in every dialog
you write in. It does not imply full WhatsApp feature parity.

## Highlights

- **A terminal client.** `whatsapptui` opens the account's conversations in a
  terminal: read them, answer, react, reply, forward, edit, delete, star and
  pin messages, archive, mute and pin conversations, send files, stickers,
  polls and contacts, and play voice notes without a window. Names and
  messages are drawn as text only - a control sequence somebody put in a name
  cannot move the cursor or retitle the window - and it opens only the links a
  conversation actually holds. What it can and cannot do yet is listed, method
  by method, in `docs/tui-parity.md`.
- **`./WhatsAppGo-x86_64.AppImage --tui`** starts the terminal client from the
  same file, before anything needs a display, and hands it every other
  argument (`--tui --profile work`). Linux and macOS only.
- **Ctrl+Enter sends; Enter starts a new line.** It also saves or posts what
  you wrote in a dialog: an edited message, a text status, a bug report, a
  group or community description.
- **The README shows the window and the terminal client**, made with
  made-up conversations.

## Changed

- **Ctrl+Enter is the send key for everyone, once.** The "Enter is send"
  setting was on by default, and the app writes every setting back when it
  quits, so every copy held "on" whether anybody chose it or not. The setting
  now lives under a new name and starts off: after updating, Enter starts a new
  line until you turn **Settings → Chats → Enter is send** back on. Ctrl+Enter
  sends either way.

- In a dialog, Ctrl+Enter confirms what was written in a field of several
  lines. A one-line field already confirms on Enter, and a destructive
  confirmation - delete, clear, unlink, remove - does not answer to it.

- A shared contact is drawn the way WhatsApp Web draws one: the name beside
  the picture, and under a rule two actions of equal width, Message and Save
  contact. Saving is new in the window; the daemon could already do it.

- Opening a conversation puts the cursor in the message box, the way WhatsApp
  Web does. A row clicked in the list used to leave the cursor where it was, so
  a letter typed straight after the click went nowhere. Channels are left
  alone: they have no box to write in, and so is a dialog that is open - a
  conversation opened behind it, from a notification, leaves the cursor in
  the dialog.

- In the terminal client, the account's own bubbles follow the terminal: the
  light green with dark words on a light terminal, WhatsApp's dark green
  (#005C4B) with light words on a dark one.

- `go generate ./cmd/whatsapptui` writes the terminal's emoji from the
  window's own list, and a test fails if the two ever disagree.

## Fixed

- "Share a contact" opens on the people who have names. The list is sorted by
  name, and anyone not in the address book has none - WhatsApp substitutes a
  masked `+972∙∙∙∙∙∙∙10`, a bare number, or a dot - so those filled all
  hundred rows and the named contacts were never reached. They now sort last,
  and are listed by their number rather than by the stand-in.

- A contact somebody shares now arrives with its number. WhatsApp's phone
  clients write the vCard's number as a grouped property, which the reader
  skipped, so the card had a name and nothing else on it. A conversation
  re-synchronised after this change fills the number in.

- Opening the window no longer draws "info query returned status 400:
  bad-request" in red across it. A profile picture was being asked for by
  phone - a status sender arrives with its device attached - and WhatsApp
  refuses an address it cannot hold a picture for. The picture is now asked for
  by person, and a row that cannot show a face quietly shows initials.

- `--screenshot-chat` opens the conversation under its name, as a click does,
  rather than "Group" or the bare number.

## Known issues

- `--tui` needs the window running on the same machine, because the terminal
  client talks to the background service the window starts; with none
  running it says so and exits (`whatsappgo-q20`).

- The terminal client cannot tell Ctrl+Enter from Enter - most terminals send
  the same key for both - so Enter sends there.

- Windows ships no terminal client, and the macOS disk image does not carry
  one either; `--tui` there reports that it is not part of the installation.

- `desktop-message-interactions` fails intermittently when the machine is
  busy (`whatsappgo-jy9`). It reads a popup 20ms after opening it, before the
  animation has finished.

- An AppImage run waits 25 seconds for a window when the session bus it
  inherits has no desktop portal on it (`whatsappgo-8ug`). Starting it with
  `QT_QPA_PLATFORMTHEME=gtk3` avoids the wait.
