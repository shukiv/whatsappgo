# WhatsAppGo v0.1.13

Four commits since v0.1.12. Animated stickers play at last - no build this
project ever published could decode one - a message that arrives late is drawn
where it happened, an emoji sent on its own is drawn large, and the strip above
the composer says how long there is to wait. It does not imply full WhatsApp
feature parity.

## Highlights

- Animated stickers play. Every published build until now was made without the
  library that decodes them, so one always said it was unavailable.
- A message that reaches the window late is drawn where it happened rather than
  under today's messages.
- A message that is nothing but emoji is drawn at twice the size, the way
  WhatsApp Web draws one.
- The scheduled-message strip says how long there is to wait, and keeps
  counting.

## Fixed

- **Animated stickers:** playing one put "Animated stickers are unavailable in
  this build" across the conversation, and it was true of every AppImage, disk
  image and installer this project has published. WhatsApp sends an animated
  sticker as an animated WebP; no Qt image plugin decodes one, so the client
  decodes it itself through libwebp - and the build looked for that library
  quietly, found nothing, said nothing, and carried on. Nothing in the release
  workflow ever installed it. The library is now installed where the builds
  run, and a packaged build that cannot play an animated sticker fails to
  configure rather than reaching somebody: `WHATSAPPGO_REQUIRE_WEBP` turns a
  missing library into an error, and both packaging scripts set it. Two
  separate faults also shared one sentence, so a sticker that is not stored on
  this computer no longer blames the build.
- **Message order:** a message that reached the window late - history filling
  in an older part of a conversation, or an attachment finishing its download -
  was appended to the end, which drew it under today's messages with a date
  separator from months ago and dragged the reader to the bottom. It is now
  placed by time and id, matching the order the daemon returns.

## Added

- **Emoji sent alone:** a message whose text is nothing but emoji is drawn at
  twice the body size. A sentence with an emoji in it is unchanged, because
  enlarging the words around it would be worse than leaving the emoji small.
- **Time until a scheduled message:** the strip above the composer named the
  moment and left the reader to work out what it meant from where they were
  standing. It now says both - "1 message scheduled for 29 Sep, 08:00 - in
  about 8 hours" - and re-reads the clock every thirty seconds, so it does not
  still claim eight hours the following morning. More than one waiting names
  the next.

## Known issues

- Windows builds still ship without libwebp, so animated stickers do not play
  there. The Linux and macOS jobs install it and their packaging refuses to
  build without it; Windows needs vcpkg wiring that has not been verified.
  Tracked as `whatsappgo-lgf`.
- An edit made on the user's phone was reported as never appearing. The three
  shapes a correction can take are all recognised now, but that particular
  message left no trace in the stored history, so it does not appear to have
  reached this computer at all. Tracked as `whatsappgo-45a`.
- `desktop-resize-rendering` aborts at teardown with a `QFontDatabase` ordering
  message. It is a race, not a regression, tracked as `whatsappgo-8hd`.
- The search panel's result count is written with `%n`, which reaches the
  reader with its brackets intact because no translation is shipped.

## Installation

Download the artifact for your platform and verify it against `SHA256SUMS`
before installation. Builds are unsigned: Windows SmartScreen may warn, and
macOS may require approval in System Settings.
