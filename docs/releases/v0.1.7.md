# WhatsAppGo v0.1.7

## Unread-message divider

- Show a centered unread-count pill on a subtle horizontal band above the first
  unread incoming message, matching the WhatsApp Web reference in both themes.
- Keep its position stable across receipts and older history pages. New incoming
  messages increase the count; duplicate updates do not. Replying clears it,
  and reopening a chat starts a fresh unread batch.
- Read the initial message page and unread boundary from one database snapshot.
  Do not guess a boundary when the required history is unavailable locally.
- Preserve messages arriving during the initial page request and ignore stale
  responses from earlier chat activations.
- Preserve bottom-opening behavior and ordinary mouse-wheel scrolling.

This release also includes all earlier desktop navigation, media sizing,
typing-status and reliability fixes documented in the
[v0.1.6 notes](v0.1.6.md).

## Upgrade and compatibility

Upgrade the desktop application and its bundled `whatsappd` and `whatsappctl`
together. Existing account profiles, settings and locally retained history are
preserved; no re-pairing or database reset is required. Disappearing-message
timers still do not expire locally stored history.

Bug reporting opens [WhatsAppGo GitHub issues](https://github.com/shukiv/whatsappgo/issues)
in the default browser. No intake key, in-app form or automatic log upload is
required. Voice and video calls remain unsupported.

## Builds and verification

Release artifacts are the Linux AppImage, Windows installer and portable ZIP,
and macOS Apple Silicon DMG, accompanied by `SHA256SUMS`. Verify checksums before
installation. Builds are unsigned: Windows SmartScreen may warn, and macOS may
require allowing the application in System Settings.

Verification uses the existing Go race/vet and desktop suites, isolated
light/dark previews and database checks, plus complete cross-platform CI before
tagging. No live WhatsApp messages or production bug reports are sent.

The release remains a draft until a human reviews and publishes it. Drafts are
not offered by the automatic update checker; the local development installation
is upgraded directly after building the tagged source.
